## 1. 資料日期差太多天

**不是資料的問題,是說法的問題。** 直接打 Worker 複核:

```
{"asof":{"spx":"2026-11-02","vix":"2026-11-02"}, ...}
```

今天是 2026-11-03(週二),資料是 11-02(週一)的收盤——這就是最新的。
使用者看到的「10/30 · 4 天前」也沒錯:10/30 是週五,在週一看確實是
最新收盤,只是 `staleDays` 數的是**日曆天**,週末兩天被算了進去。

一個交易日的落後被講成「4 天前」,於是每個週一、週二都在發假警報。

**改法**:新增 `openDaysBehind()`,只數週一到週五。顯示改講交易日:

| 情況 | 原本 | 現在 |
|---|---|---|
| 週五收盤,週一看 | 資料日期 2026-10-30 · 3 天前 | … · 最新收盤 |
| 週五收盤,週二看 | 資料日期 2026-10-30 · 4 天前 | … · 落後 1 個交易日 |
| 真的落後一週 | 資料日期 2026-10-26 · 8 天前 | … · 落後 5 個交易日(紅字) |

**閘門沒有跟著改。** `gateReasons` 仍用 `staleDays`,STALE=4 是策略參數,
改它是獨立的策略變更,不該在顯示層偷做。日曆天與門檻搬到 tooltip,
查得到但不佔版面。有一道測試專門釘住「閘門不可改用交易日」。

已知限制:不含美股假日表,國定假日會多算一天。

## 2. 持倉就是我貼的

原本「套用」只寫入貼上來的代碼,沒提到的原封不動留著。賣光的部位
於是變成幽靈,繼續被算進總值、繼續產生下單建議。

**改法**:`diffHoldings` 把沒出現的代碼視為已出清,`applyParsed` 寫 0
並刪掉成本(不刪的話下次買回來會沿用上一輪的成本,未實現損益從此是假的)。

風險反過來了——只貼到半個畫面會洗掉好資料。所以**每一檔要歸零的都
列成預覽表裡的一行**,紅字,按「套用」之前就看得見:

```
代碼          目前股數   解析股數   差額      解析成本
00670L           1,000     1,000      —      170,000
00640L             300       400    +100       38,000
00988A 未出現    4,000         0  -4,000          —
00653L 未出現    1,500         0  -1,500          —

3 檔要改。套用後持股市值會從 628,075 變成 516,080(-111,995 TWD)。
這段文字裡沒出現、套用後會被歸零的:00988A(4,000 股,約 57,440)、
00653L(1,500 股,約 64,590)。…如果券商畫面要捲動、你只貼到一半,
請把剩下的一起貼上再套用,不要直接按。
```

### 這個改動帶出的真 bug:假回撤

實測:兩檔歸零 112k,月檢立刻顯示 **dd 從 0.0% 變成 -13.5%**。

峰值只會往上不會往下,組合總值一掉就等於憑空出現一段回撤——而回撤
決定分層抄底,-30% 就開始建議加碼。這是我自己的改動造出來的。

**刻意不自動平移峰值。** 賣掉的錢可能還在帳戶裡(那就該去填現金,
總值自然回來),也可能已經轉走(那才該重設峰值)。只有本人知道是
哪一種。所以在月檢跑完之後明說,並指出那兩顆按鈕在哪。

## 3. 目標配置的 DEBUG

引擎一律正規化,所以合計不是 100% 不會「算錯」——但畫面上的數字跟
引擎實際在用的不一樣,而人是照畫面做決定的。填 30/15/10/10/15/5
(合計 85)看起來剛好,實際每一檔都被縮小到 28.2/14.1/9.4/9.4/14.1/4.7。

新增 `auditWeights()`,三種會咬人的設定錯誤:

1. 合計加現金不是 100%
2. 目標權重 0 的標的(再平衡會要求把它全部賣出)
3. 代碼重複(後面那列會覆蓋前面那列)

加上一顆「幫我改成合計 100%」。填進去的就是引擎本來在用的那組比例,
所以這一按**不改變任何決策**,只是讓畫面跟引擎對齊。

修正值用**最大餘數法**取到 0.1 個百分點:各自四捨五入的話六檔加起來
還是 79.8% 或 80.2%,按了修正畫面上仍是紅字。實測:

```
28.3 + 14.1 + 9.4 + 9.4 + 14.1 + 4.7 = 80.0  + 現金 20% = 100.0%
```

目標權重的輸入框改成 `step="0.1"`,否則取整會把修正值打回原形。

## 4. 總投入金額拿掉

持倉已經是貼券商庫存貼進來的,總資產卻要人另外填一次。同一個數字
維護兩份,填舊了就把「自動分配」與「四年模擬」一起算歪,而且錯得
毫無異狀。

整段刪掉,兩處都改走 `capNow()` = 持股市值 + 現金。

**報價缺一檔時回 `null` 而不是低估值**:`totals().V` 在報價缺失時會
少算那一檔,拿它當總資產會配出偏小的目標股數——等於要人賣掉本該
留的部位。寧可擋下並說「請先按更新」。

「自動分配」順便搬進「目標配置」卡片裡,它本來就是依那份配置動作。

## 5. 讀圖能力(最重要的一項)

四個改動:

**辨識參數**。預設的自動分頁(psm 3)會把券商表格切成奇怪的區塊;
固定成「一整塊文字」(psm 6)準很多。加上保留字距,以及把中文與
全形符號擋在白名單外——那些字本來就不讀,留著只會讓 `0` 被認成
形狀相近的漢字。

**兩種前處理,各認一次**。灰階保留筆畫漸層,`0` 容易被認成 `8`;
二值化把筆畫切乾淨,但對比不足的區塊會整塊消失。只跑一種就是賭
這張圖剛好適合那一種。二值化的門檻取整張圖的灰階平均,不是固定
數字——券商的深色底有深灰也有純黑。

**贏家由解析器自己挑**,不是用字數猜。解析器本來就有一道核對
(「股數 × 現價 ≈ 市值」),對得上幾列就是真的讀對幾列。排名順序:
對上的列數 → 成本複核過的列數 → 總列數。

**成本改用「買入價 × 股數」**。使用者說得對:畫面上就印著買入價和
目前價,成本根本不必靠損益率的符號去猜。

```
目前價 ≈ 市值 ÷ 股數      ← 認得出來
買入價 = 這一列另一個同量級的小數
成本   = 買入價 × 股數,賺賠由兩個價格的大小直接決定
```

同量級的小數不只一個就放棄,退回原本的三數互推——猜錯價格會把成本
整個算歪。兩條路都走得通時互相複核,差超過 2 個百分點就標「需確認」。

### 實測

合成一張深色底白字的券商畫面(4 列,用當下的真實報價生成),走完整條
截圖 → 辨識 → 解析:

```
3.7 秒,4 列全中,4 列全部 sure + costSure

00670L  1,000 股  成本 170,000  ✓
00647L  2,000 股  成本 290,000  ✓   ← 損益率的負號不在圖上
00631L    500 股  成本  18,250  ✓
00640L    400 股  成本  38,000  ✓
```

00647L 那一列的 `-5.10%` 故意只印 `5.10%`(模擬 OCR 吃掉負號),成本
仍然算對:買入價 145 高於目前價 137.6,賠的,不必靠符號。

### 實測抓到的 bug

第一次跑的時候 Tesseract 把 `00647L` 認成 **`00647.`**。`fixOcrCodes` 的
混淆群組裡沒有句點,而且 token 正規表示式在句點處斷開,`00647` 長度 5
跟長度 6 的代碼永遠對不上——**那一列整個消失了**。

舊版只是少一列(會被「幽靈持股」警告抓到);新版「貼上的就是完整庫存」
之下,少一列等於**那個部位被歸零**。一個句點無聲賣掉一檔。

修法:句點加進 `1lI|L` 那一組,token 正規表示式含 `.`。仍然只准差一個
字元且必須唯一命中,所以 `184.85` 這類價格動不了(有測試釘住)。

## 6. 最壞情況

總額來源跟著改成組合總值。輸出重寫——原本只印三個數字,最該看的
那一件事(「最壞大概會少掉多少錢」)還要自己減:

```
以你現在的 717,105 TWD 出發,4 年後(5,000 條路徑,取樣 1990–2026):
最壞的 5% 剩 552,755 TWD(少 164,350)
中位 1,303,591 TWD
最好的 5% 到 2,673,260 TWD
4 年後還是虧的機率 11.9%

這是策略本身的波動,不含你何時進場。
看不下去「最壞的 5%」那個數字,就代表投入金額太大。
```

(5,000 條路徑的取樣誤差),不是新的偏差。

## 自我演化:這一輪學到的

**1. 「資料太舊」先去問資料源,不要先改顯示。**
直接 `curl` 打 `/signal` 花十秒,結果資料是最新的——問題根本在單位。
如果一開始就去改快取或加重試,會修一個不存在的 bug。

**2. 使用者說「照片裡有買入價你都沒抓」時,他講的是事實。**
我上一輪花了很大力氣做「三數互推符號」,而正確答案一直印在畫面上。
先看資料裡有什麼,再決定要推論什麼。

**3. 把一件事變成「真相」就要重新算一次風險。**
「貼上的就是完整庫存」讓兩個原本無害的狀況變成會賠錢的:
(a) OCR 掉一個字元 → 那個部位被歸零;(b) 總值下降 → 假回撤推動抄底。
兩個都是實測跑出來的,不是讀程式碼讀出來的。**改語意之後要把
整條路重跑一遍,不是只跑新寫的那幾行。**

**4. 突變測試又抓到一行死碼。**
`if (t < a) return 0;` 拿掉之後測試全綠——因為下面的迴圈在那個情況
本來就一次都不跑。看起來有在防,其實什麼都沒防。刪掉。

**5. 突變測試抓到兩道「測了等於沒測」。**
一道的前提是錯的(兩條路剛好算出同一個答案,觀察不到差別),另一道
被更前面的過濾器先擋掉了,根本走不到要測的那行。**測試綠不代表它
在守著什麼**——37 道突變全部跑紅才算數。
